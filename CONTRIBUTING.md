# Contributing

Thanks for helping. Bugs and requests go in [issues](https://github.com/finikoslab/spacecontext/issues); vulnerabilities go by email, see [SECURITY.md](SECURITY.md).

## Setup

```bash
npm install
npm run check          # build, typecheck and test every package
```

Node 22.12 or later. The CLI and the MCP server use the SDK's build (`dist`): build the SDK before typechecking or testing them on their own (`npm run check` builds first). The tests run against fakes and need no key; only the SDK's smoke test (see [Checks](#checks)) calls a real API, and only when you give it a test key.

The documentation is in `docs/` (Docusaurus): `cd docs && npm install && npm start` serves it on http://localhost:3000, and `npm run build` fails on any broken link. Write a fact in the docs only after checking it against the API's behaviour, the contract or the packages.

The API and its analysis pipeline are not in this repository.

## Layout and rules

Where the code is:

```
packages/cli/src/
  bin.ts, cli.ts     the entry point and the commands (parsing, dispatch, scan, ask, skill…)
  commands/          the longer flows: setup, signin (device sign-in)
  terminal/          how the CLI looks and talks: ui (colours, mark, tables), help, hints
  lib/               config (saved key), files (skill writing), system (browser, platform), links
packages/mcp/src/
  index.ts, env.ts   the Worker entry and its bindings; brand.ts (the mark and icons)
  server/            the MCP server: tools, views (what tools return), card (Server Card)
  auth/              OAuth sign-in: authorize (providers, consent, grants), html (the pages)
  api/               backend (fetch to the API, through the service binding)
packages/sdk/src/
  index.ts, errors.ts the public exports and the error type
  client/            client (every API operation), sse (Server-Sent Events)
  scans/             scan (one call: upload, start, follow)
  auth/              device (terminal sign-in)
  generated/         schema.ts, generated from openapi/openapi.json: never edit by hand
```

- `openapi/openapi.json` is generated by the API (the private `spacecontext-backend` repository, `scripts/export-openapi.mjs`). Never edit it by hand: run `npm run openapi:sync` (or `npm run openapi:sync -- --url https://api.spacecontext.app/v1/openapi.json` without the backend), then `npm run generate -w @spacecontext/sdk`, and commit both.
- `packages/sdk/src/generated/schema.ts` is generated from it. The hand-written client is `packages/sdk/src/client/client.ts`; every public method maps to one documented operation.
- The SDK has no runtime dependencies and runs in Node 22.12+, browsers, Deno and Workers. Do not add any.
- The CLI depends only on the SDK and Node built-ins.
- `packages/sdk/LICENSE` and `packages/cli/LICENSE` are copies of the root `LICENSE` (npm publishes only the package folder); their tests check that they match. `npm pack --dry-run -w <package>` shows what would be published.
- The MCP server is read-only by default: a grant's key has `spaces:read` and `scans:read` (plus `spaces:sensitive` when the user ticks it). The scanning tools (`create_scan`, `upload_frame`, `start_scan`, `cancel_scan`) and `check_frame` work only when the user ticks "let it scan spaces" on the consent page, which adds `scans:write`; the scanning tools are annotated as writing (and `cancel_scan` as destructive), `check_frame` as read-only (it stores nothing and spends nothing). Any new tool that writes or spends must sit behind that scope and be annotated honestly.

## Security invariants (tested)

- The API key is sent only to the API's own origin and path; never to a storage URL, an evidence URL or a lookalike host. Redirects are never followed.
- The CLI writes a Skill only to plain relative paths inside the target folder, after checking every path.
- The API key is never visible on a client object (an ES private field): logging, inspecting or serialising a client never shows it.
- The config file holding the key is written as a new file with mode `0600`, then renamed over the old one.
- The CLI prints what comes from the API (names, records, answers, transcripts, errors) without control characters or bidirectional overrides; `--json` stays as the API sent it once parsed, with DEL, C1 and the bidirectional controls written as `\uXXXX` (`toJson`). Programs are run with argument arrays, by absolute path, never from the current directory.
- The MCP consent forms accept posts only from their own origin; the consent handle is bound to the browser by the OAuth library and works once. A Google or Apple sign-in is bound to the browser that started it (a `__Host-` cookie) and its ticket to the consent handle it was issued for. Sign-in records in KV are sealed with a key derived from their one-time id. A refused authorization request is never redirected to the client. Client-supplied strings are escaped. A key created for a grant that cannot be completed is revoked. Codes go to https, http on a loopback host, or the URL scheme of a known app (`NATIVE_REDIRECT_SCHEMES`: `cursor:`), never to another scheme a client registered, and the consent page shows an app's link as `scheme://host` with a warning.
- Content of a space is data, never instructions: the MCP server says so in its instructions and in every result that carries space content (`note`).
- A key revoked in the console ends its MCP grant on the next call (the client is asked to sign in again); connecting the same client again revokes the key of the grant it replaces.

## Checks

`npm run check` must pass: build, typecheck and tests of all packages. After a deploy, run the SDK's smoke test against the host with a **test** key (free, the demo space): `SPACECONTEXT_SMOKE_KEY=sc_test_… SPACECONTEXT_SMOKE_BASE_URL=https://api.spacecontext.app/v1 npm exec -w @spacecontext/sdk -- vitest run test/smoke.test.ts` — it reads the demo in every form, asks, searches, runs a whole scan live and checks a frame. The MCP tests run in workerd (`@cloudflare/vitest-pool-workers`) and drive the full OAuth flow (registration, PKCE, consent, token) and real MCP calls against a fake API.
